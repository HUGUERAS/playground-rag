# Definition of Done GeoAdmin Docs

## Um documento e considerado pronto quando

- tem papel claro dentro da estrutura documental;
- nao conflita com a precedencia editorial da raiz;
- usa nomenclatura consistente com o app e com o PRD;
- separa requisito atual de backlog futuro;
- registra lacunas reais em vez de esconder ambiguidade.

## Um requisito funcional esta pronto para virar codigo quando

- aparece ou no PRD ou no mapeamento funcional com objetivo claro;
- tem dados de entrada e saida identificados;
- tem dependencia tecnica conhecida;
- possui validacoes ou erros esperados minimamente descritos;
- ja esta posicionado no roadmap ou backlog.

## Um item nao esta pronto quando

- depende de HTML bruto para ser entendido;
- existe apenas como ideia em prompt;
- conflita com nome ou comportamento visivel nas telas;
- mistura regra de produto com sugestao vaga de implementacao.
